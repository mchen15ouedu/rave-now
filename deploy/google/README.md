# Tracker bridge connection

This optional, free Apps Script bridge connects a spreadsheet you administer. It reads the **Name** column B in **Artist List** and **Promoter List**. `ensureArtist` appends a name, in Artist List column B. It preserves Instagram and Notes values and copies the previous row's formatting. Case, accents, and repeated spaces are ignored for duplicate checks. A script lock prevents simultaneous requests from adding duplicates, and rich text keeps formula-looking names literal.

The read-only `readShows` action reads **Upcoming Shows** from the same configured workbook. It returns only **Artist**, **Event**, **Location**, **City**, **Address**, **Ticket Link**, **Show Time**, and **YouTube (Most Popular Song)**, in that order, plus **Style** when present. Style is located by its normalized header, returned as public music-style text, and never inferred or changed by event writes. The bridge locates columns by normalized header names, accepts reordered columns, and rejects missing or duplicate required headers. It excludes every unrelated column. Reads allow at most 10,000 data rows and 100 source columns; larger sheets fail visibly rather than returning a partial event list. Show dates are returned as displayed in the sheet, without claiming a last-edit timestamp. It does not research events. The authenticated `ensureEvent` action accepts independently verified facts from the app server. Under the same writer lock, it adds a performer/event row, ignores an existing complete event, or fills only blank matching fields. Existing formulas, populated facts, unrelated columns, merged/protected cells, and validation rules are preserved; ambiguous or conflicting matches are reported for review. A Source URL/Source Link column is used only if it already exists; no column is created. Evidence is also retained in the private HF submission record. The server never retries an event POST automatically.

1. Prepare your own workbook with the three named tabs and required headers above. In it, open **Extensions → Apps Script**. Paste `artist-catalog-bridge.gs` into `Code.gs`, use the **V8** runtime, and save the project as **Rave Now Tracker Bridge**.
2. In **Project Settings → Script Properties**, configure `CATALOG_WORKBOOK_ID` with your workbook's ID and `CATALOG_ARTIST_SHEET_ID`, `CATALOG_PROMOTER_SHEET_ID`, and `CATALOG_SHOW_SHEET_ID` with the respective tab IDs. A tab ID is its numeric `gid` in the tab's URL; IDs must be distinct and nonnegative. The script rejects missing or invalid identities instead of opening any default workbook. Requests cannot override these server-side properties.
3. Generate a random key of at least 32 characters. Add it as the Script Property `ARTIST_CATALOG_SECRET`. Keep it out of repositories, browser JavaScript, logs, and URLs.
4. Use **Deploy → New deployment → Web app**. Execute as the spreadsheet owner and allow **Anyone** to reach the endpoint. The bridge rejects calls without the key. Review Google's authorization request before granting it: Apps Script's `openById` requires the broad Google Sheets scope, even though this code uses only the configured workbook and tab IDs. No Drive, Gmail, or external URL-fetch access is requested by the script.
5. Save the deployment's HTTPS `/macros/s/…/exec` URL as the server Secret `ARTIST_CATALOG_URL`, and the same key as its Secret `ARTIST_CATALOG_SECRET`. Restart the app if its environment is not refreshed automatically.
6. To use current event rows through this bridge, set `BROWSER_SOURCE_MODE=apps-script` in the server environment. This reuses the same URL and secret. Verify a recent Upcoming Shows entry appears in searches. The event provider caches successful reads for up to 60 seconds; configured failures are reported without falling back to an old snapshot.
7. Verify the artist suggestions, search an existing show artist absent from Artist List, then confirm its readable name appears once in column B. Search a case/accent variant again and confirm no duplicate. Existing Instagram and Notes cells should remain intact.

The app server sends the key only in a JSON POST body to `script.google.com`. It fetches Google's redirected ContentService output with a fresh GET without forwarding the key. Catalog browser responses contain artist names and addition status only; show browser responses contain the app's ordinary public event fields. The server validates event rows as bounded arrays of strings and caps bridge response bodies at 2 MiB. Configured provider failures are reported; they do not silently fall back to an old catalog or pretend that a write succeeded.

Keep column B's header exactly **Name**, retain all three tab names and configured IDs, and retain the eight event headers, or update the checked configuration deliberately. After editing the script, publish a new deployment version. Reading current shows uses the existing Google Sheets OAuth scope and shared key; it adds no authorization scopes.

For a read-only Sheets API source instead of the bridge, use `BROWSER_SOURCE_MODE=live`, configure your `SPREADSHEET_ID`, and optionally set `SHEET_ID` or use the `SHEET_NAME` selector (default **Upcoming Shows**). Provide Google credentials through your deployment's secret manager or an attached cloud identity. Live messaging also requires `SPREADSHEET_ID` plus its messaging configuration. The public demo includes no owner's source IDs or credentials and works offline without either adapter.

Google documentation: [bound scripts and web apps](https://developers.google.com/apps-script/guides/bound), [openById authorization](https://developers.google.com/apps-script/reference/spreadsheet/spreadsheet-app#openbyidid), and [ContentService redirects](https://developers.google.com/apps-script/guides/content).

## Contribution processing

Publish the reviewed bridge source as a new version of the existing deployment to enable `ensureEvent`. Its execution identity, shared secret, URL, and existing Sheets OAuth scope remain the same. Enable the HF contribution worker only after this version is live. Test duplicates and inspect confirmed additions in Artist List and Upcoming Shows. The server invalidates its read cache after a confirmed event add or merge.
